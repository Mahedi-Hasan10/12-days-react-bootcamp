Problem → solution

Maintaining large CSS files becomes difficult

Problem

Custom class names drift. Dead CSS piles up. Two “cards” diverge by 4 pixels.

Solution

Utility-first: small, reusable classes that map 1:1 to CSS properties.

Technology: Tailwind CSS. Result: faster, more consistent UI — if you already understand CSS.

What is it?

Tailwind is a utility-first CSS framework

What

A catalog of classes like mt-4, flex, text-teal-700.

Why

Style in HTML without inventing a new stylesheet per component.

How

Add the library, then compose classes on elements.

It does not replace CSS. It generates CSS for you from class names.

Setup for beginners

Play CDN — good for class, not the final production story

<script src="https://cdn.tailwindcss.com"></script>

Why CDN today

No Node install. Refresh and classes work. Matches a beginner laptop lab.

Honest caveat

The Play CDN is for development. Real apps later use a Tailwind build so unused CSS is stripped. You will see that around React week.

Paste the script in head. Confirm network. If blocked, have a local fallback plan. Do not spend 40 minutes on npm today.

Typography

Size, weight, leading — still the same ideas

Flexbox in Tailwind

Same navbar. Classes instead of a CSS block.

<header class="flex items-center justify-between gap-4 px-6 py-4">
  <strong>Harbor Bean</strong>
  <nav class="flex gap-5">...</nav>
</header>

Map: flex → display:flex · items-center → align-items · justify-between → space-between · gap-4 → gap.

Grid in Tailwind

Columns as a class, not a template string you memorize twice

  <article class="...">Cold brew</article>
</div>

  Latte
</article>

Use shadow-sm on cards. Huge shadows on every box look like a 2014 tutorial. Restraint is a skill.

Responsive prefixes

Mobile-first, same as yesterday — now in the class list

<h1 class="text-3xl md:text-5xl">Harbor Bean</h1>
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3">
PrefixMeaning (approx.)
(none)All sizes — your mobile default
sm:~640px and up
md:~768px and up
lg:~1024px and up

How prefixes work

Unprefixed rules apply. Prefixed rules add from that width.

Think

grid-cols-1 md:grid-cols-3 equals yesterday’s 1-col default + a min-width 768 query.

Trap

Do not start with md: only. Then phones get no layout classes.

Hover and focus

States are prefixes too

<a class="rounded-lg bg-teal-700 px-4 py-2 text-white hover:bg-teal-800 focus:outline-none focus:ring-2 focus:ring-teal-500">
  Order now
</a>

Hover is for pointers. Focus is for keyboard users. Never skip focus on buttons and links.

Interactive question

A button looks fine until you Tab to it and see no outline. What did the designer probably remove — and what should they add back?

Hint: outline-none is only OK if you replace it with a visible focus:ring.

Many students copy “remove outline”. Make this a hard rule for the rest of the course.

When not to Tailwind everything

Utilities are a default, not a religion

Still write CSS when

A rare animation, a one-off blog article layout, or a design token you will reuse 40 times as a component later.

Beginner rule this week

Landing pages: utilities. If a class string repeats 5 times, you may extract a small custom class — or wait for React components.

Recap

What we learned

Utility-first

Compose known CSS properties as classes.

Scale

Spacing and color numbers keep UI consistent.

Layout

flex, grid, gap — same as Day 3.

Responsive + states

md:, hover:, focus:

Common mistakes

  • Using Tailwind without understanding CSS — then guessing class names forever.
  • Only writing md: classes so mobile has no styles.
  • Removing focus outlines and not replacing them.
  • Fighting utilities by adding a huge extra CSS file on day one.
  • Typos: justfiy-between fails silently.

Key takeaways

  1. Tailwind is CSS with a shared vocabulary, not magic.
  2. Utility-first trades class-name invention for longer HTML.
  3. Mobile-first prefixes match yesterday’s media queries.
  4. Hover is nice; focus is required.
  5. CDN is for learning. Production will use a build later.
