API integration

Fake Store is enough for v1

// src/api/products.js
const BASE = "https://fakestoreapi.com";

export async function fetchProducts() {
  const res = await fetch(BASE + "/products");
  if (!res.ok) throw new Error("Could not load catalog");
  return res.json();
}

Optional: /products/:id for details, or filter the already-loaded array by id.

Add to cart

Update by id. Do not duplicate lines blindly.

function addToCart(product) {
  setCart(prev => {
    const found = prev.find(i => i.id === product.id);
    if (found) {
      return prev.map(i => i.id === product.id ? { ...i, qty: i.qty + 1 } : i);
    }
    return [...prev, { id: product.id, title: product.title, qty: 1 }];
  });
}

const cartCount = cart.reduce((n, i) => n + i.qty, 0);
Cart drawer / full page is bonus. v1 is counter + optional simple list under the nav. Quantity increment is the teaching point.

Responsive UI

Phone first, then add columns

  • One column of cards on small screens.
  • Nav stacks or compresses; cart badge stays visible.
  • Details: image on top, text below; side-by-side from md:.
  • Search and filters should not overflow horizontally.

Code organization

Helpers stay out of giant App files

filterProducts(products, query, category)

Pure function. Easy to reason about. No hooks inside.

formatPrice(n)

$ + two decimals. Use it on cards and details.

Debugging

A short loop when something is “blank”

  1. Console: did fetch return an array?
  2. React DevTools: is state what you think?
  3. Network tab: 200 vs CORS vs 404
  4. Conditional UI: are you stuck on loading?
  5. Keys and map: is the array empty after filter?
Demo DevTools Components panel on a half-built shop. Show cartCount derived vs stored incorrectly.

Common React mistakes on project day

Fetch in render

Loops. Put it in useEffect.

Mutating cart

cart.push will haunt you. Spread.

Index keys

Fine for a static demo; painful when the grid filters.

Prop drilling panic

For this size, passing props is OK. No context library required.

Common mistakes to avoid tonight

  • Building the cart before the catalog loads.
  • Copy-pasting 4 slightly different cards.
  • Storing filtered products instead of deriving them.
  • Ignoring mobile until “later.”
  • Scope creep: payments, admin, five extra pages.

Key takeaways

  1. Developers plan components and state before they type.
  2. App owns shared data. Children emit events.
  3. API failures are a UI feature.
  4. Tailwind is speed — after the structure works.
  5. v1 is a checklist, not a dream.
