Problem → solution

HTML alone cannot keep a brand consistent

Problem

If every heading has its own color in HTML, changing the café brand from green to navy means editing every page.

Solution

One stylesheet. Change h1 once. The whole site updates.

Technology: CSS. Result: look is reusable, not copy-pasted.

What is it?

CSS is the language of presentation

Cascading Style Sheets describe how HTML should look: color, type, space, and placement.

What

Rules that target elements and set properties.

Why

Separate meaning (HTML) from appearance (CSS).

How

Link a .css file. The browser applies matching rules.

Real world

Same HTML. Different CSS. Different product.

News site

Dense type, thin margins, high contrast.

Café menu

Warm colors, large headings, photo backgrounds.

Bank app

Calm navy, tight spacing, clear buttons.

The structure can be similar. The CSS is the personality.

How we attach CSS

Three ways. One professional habit.

MethodWhenBeginner rule
Inline style=""Quick testAvoid in real pages
<style> in <head>Tiny demosOK for 10 lines
External .css fileEvery projectThis is the default
<link rel="stylesheet" href="styles.css">
Show the link in head. If CSS “does nothing”, first check the path — same mistake as broken images on Day 1.

Syntax

Selector, then a block of declarations

h1 {
  color: #0d6b56;
  font-size: 32px;
}

Selector

h1 — who we target

Property

color — what we change

Value

#0d6b56 — the choice

Forget a semicolon and the next line may silently fail. Always close declarations.

Selectors

Name the element, the group, or the one-off

p { color: #5b677a; }        /* all paragraphs */
.card { padding: 20px; }    /* class="card" */
#hero { min-height: 240px; } /* id="hero" */

Element

Broad. Good for body, headings.

Class

Reusable. This is your daily tool.

ID

Unique. Use rarely in CSS.

Interactive question

If both p { color: navy } and .bio { color: teal } match a paragraph, which color wins?

Hint

Classes are more specific than element names.

Rule of thumb

Prefer classes. Avoid !important as a beginner habit.

Demo in DevTools: toggle classes. Mention cascade = last equal-specificity rule wins, plus source order.

Colors

Name it, number it, or mix it

Names

color: teal;

Hex

color: #0d6b56;

RGB / RGBA

color: rgb(13, 107, 86);

Pick a small palette: ink, muted, accent, background. Do not invent a new color for every heading.

Backgrounds

Fill the box behind the content

.hero {
  background-color: #1c2740;
  background-image: url("beans.jpg");
  background-size: cover;
  background-position: center;
}

If text sits on a photo, darken the image or add a solid overlay. Contrast is accessibility, not decoration.

Fonts

Type is 90% of a beginner’s “design”

body {
  font-family: "Figtree", sans-serif;
  font-size: 18px;
  font-weight: 400;
  line-height: 1.5;
}

Why

A readable body font + one heading font feels like a brand.

How

Link Google Fonts in head, then name the family in CSS.

Live-add Figtree like this deck. Warn: system fonts work offline; Google Fonts need network.

Text styling

Guide the eye without shouting

h1 { letter-spacing: -0.03em; }
.lede { text-align: left; }
a { text-decoration: none; }
.muted { text-transform: none; }

Real world

Café tagline: slightly larger, muted color, extra line-height. Price: bold. Legal text: smaller.

Problem

Elements are boxes. Spacing fights feel “random” until you see the model.

Margin, padding, border, and content width are not decoration. They are the geometry of the page.

If a card feels cramped, should you grow margin or padding first?
Let them guess. Reveal next: padding = inner air; margin = space between boxes.

Box model

Every element is a rectangle

Margin
→
Border
→
Padding
→
Content

What

How the browser sizes and spaces a box.

Why

So cards, buttons, and photos align predictably.

How

Inspect an element. DevTools draws the four layers.

Margin

Space outside the border — between neighbors

.card {
  margin-top: 24px;
  margin: 0 auto 32px; /* top | horizontal | bottom */
}

Vertical margins can collapse. Two 20px margins stacked may become 20px, not 40px. That surprises everyone once.

Padding

Space inside the border — around the content

.card {
  padding: 20px;
  padding: 16px 24px; /* vertical | horizontal */
}

Real world

A profile card without padding glues the photo to the edge. Uncomfortable.

Tip

Buttons need padding more than huge font size.

Border

The edge of the box — line, radius, or none

.card {
  border: 1px solid #d8d2c6;
  border-radius: 16px;
}
img { border-radius: 50%; } /* circular avatar */

Width and height

Size the box — then decide what “100%” means

.card {
  width: 380px;
  max-width: 100%;
  box-sizing: border-box;
}
img { width: 120px; height: 120px; object-fit: cover; }

border-box includes padding and border in the width. Set it on * early. You will thank yourself.

Interactive question

What is the difference between margin and padding?

Margin

Pushes other elements away. Background does not fill it.

Padding

Grows the clickable/colored area. Background does fill it.

Display

Tomorrow we add flex and grid. Today: know these four.

Position

Most of the time, stay in normal flow

  • static — default
  • relative — nudge; also an anchor
  • absolute — taken out; relative to nearest positioned ancestor
  • fixed — sticks to the viewport

Beginner trap

Do not position: absolute every box to “make layout”. That is how pages shatter on a phone.

Demo a small badge on an avatar with relative parent + absolute child. Then stop. Layout systems come Day 3.

Units

Pixels are easy. Relative units scale.

px

Fixed. Borders, tiny offsets.

%

Of the parent. Widths.

rem

Of root font size. Type and spacing.

vw

1% of viewport width. Use sparingly.

html { font-size: 16px; }
h1 { font-size: 2rem; } /* 32px if root is 16 */

Basic responsive

Do not force a 380px card on a 360px phone

.card {
  width: 380px;
  max-width: 100%;
}
img { max-width: 100%; height: auto; }

This is not full responsive layout yet. It is the minimum so nothing overflows. Media queries arrive tomorrow.

Recap

What we learned

Job of CSS

Presentation, separate from HTML meaning.

Rules

Selector + properties. Classes are the workhorse.

Look

Color, background, font, text.

Geometry

Box model, display, position, units, max-width.

Common mistakes

  • Styling with inline style everywhere — unmaintainable.
  • Confusing margin (outside) with padding (inside).
  • Setting width 400px with no max-width: 100%.
  • Using position: absolute to fake a layout.
  • Forgetting the CSS file path — “CSS is broken” is often a 404.

Key takeaways

  1. HTML structures. CSS presents. Keep them apart.
  2. Prefer classes. Keep selectors simple.
  3. Every element is a box: margin, border, padding, content.
  4. border-box + max-width: 100% prevent early chaos.
  5. Save → refresh → inspect. DevTools is part of CSS.
