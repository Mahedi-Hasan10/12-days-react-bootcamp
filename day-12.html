Interactive question

What is the difference between npm run dev and npm run build?

A

They are the same. Build is a nickname.

B

Dev is a local server with hot reload. Build outputs static files for hosting.

C

Build uploads the app to GitHub automatically.

B. C is a common mix-up with CI. GitHub stores source; Netlify/Vercel (or Pages) can host the build.

Project review

Read your app like a teammate, not like its author

  2. Do component names match the UI?

  4. Are loading and error visible?

What is it?

Refactoring is improving code without changing what it does

Rename, extract, delete duplication. The shopper still adds to cart. You can still explain every file.

Why

Presentation day is when messy App.jsx fights you on stage.

How

One change, then run the app. Repeat.

Real world

Teams refactor before adding the next feature.

Safe refactors today

  • Extract a 80-line card into ProductCard.jsx.
  • Move fetch into api/.
  • Rename data to products.
  • Delete unused imports and commented-out experiments.
  • Do not rewrite in TypeScript an hour before you present.

Debugging on ship day

Blank deploy vs blank localhost

Local only

Wrong folder, crashed Vite, API blocked, React error overlay.

Live only

Wrong build folder, SPA refresh 404, mixed HTTP API, missing env.

Always reproduce locally with a production build: npm run build then preview.

What is it?

Git is a history of your project. GitHub is a remote copy.

You snapshot working moments. You can go back. You can share without emailing zip files.

Why

Jobs, teams, and your future self all read history.

How

Init → add → commit → remote repo → push.

Classroom rule

Never commit passwords, API keys, or .env with secrets.

High level only. Do not deep-dive rebase. If someone has never installed git, pair them. Demo GitHub.com new repo UI.

The four verbs

CommandMeaning
git initStart history in this folder
git add .Stage files (respect .gitignore)
git commit -m "…"Save a snapshot with a message
git pushSend commits to GitHub

A “repo” is that folder with history — local, remote, or both.

What belongs in git

Commit these

Source, package.json, README, public assets, .gitignore.

Never commit these

node_modules, dist (usually), .env with keys, personal tokens, private student data.

# .gitignore
node_modules
dist
.env
.env.local

Instructor live coding

From folder to GitHub (happy path)

  1. Confirm .gitignore exists
  2. git init
  3. git add . then git status — scan for secrets
  4. git commit -m "Add shop v1"
  5. Create empty GitHub repo → follow the shown remote add + push

If auth fails, screenshot the error and continue the deploy with a zip. Do not leak tokens in chat.

Static host

The host does not run useState on a server. It serves HTML, JS, and CSS. React runs in the visitor’s browser.

Deployment concepts

Hosting is “put dist on a public URL”

What

A company serves your static files over HTTPS.

Why

Classmates and employers can open the app without cloning.

How

Drag the dist folder, or connect the GitHub repo so every push rebuilds.

Deploy React

Netlify or Vercel — pick one for class

Drag and drop

Run npm run build locally. Upload dist. Fastest first win.

Git-connected (concept)

Connect repo. Build command npm run build. Publish directory dist. Later pushes update the site.

Exact buttons change. The idea does not: build output + public URL.

SPA refreshes

If you add real routes later, configure redirects

A static host looks for a file named like the path. React Router paths are not real files. Tell the host: “serve index.html.”

If you stayed on selectedId state with no router, refresh on the home URL already works.

Environment variables basics

Config that should not be pasted into source

Local

.env / .env.local — listed in gitignore. Vite exposes only names that start with VITE_.

Host dashboard

Set the same names in Netlify/Vercel UI. Rebuild after changes.

Anything in a Vite frontend is visible to the browser. Never put a secret private key in frontend env. Public read-only API keys are a judgment call; prefer key-free APIs when you can.

Keep this conceptual. Do not have students paste keys into the chat. If they used only Fake Store, they may have zero env vars — that is success.

Common presentation mistakes

  • Apologizing for 90 seconds before the first click.
  • Reading every line of App.jsx instead of showing the user path.
  • Claiming “it works on my machine” with no README.
  • Hiding the loading and error states — those are features.

Common mistakes to avoid after class

  • Force-pushing to rewrite history you already shared — ask first.
  • Committing .env “just for now.”
  • Only ever running dev and being surprised by production.
  • Collecting 20 tutorials instead of finishing one app.
  • Hiding broken deploys instead of writing the error down.

Key takeaways

  1. Working software plus a URL is a real portfolio piece.
  2. Git is history; GitHub is the shared copy.
  3. Build, then host static files. React still runs in the browser.
  4. Secrets do not belong in frontend git.
  5. After React: router, a11y, TypeScript, a backend — in that spirit of sequence.
