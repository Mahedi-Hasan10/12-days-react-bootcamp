What is it?

State is data a component remembers over time

When state changes, React re-renders that component and its children. The screen is a snapshot of state.

Why we need it

Clicks, typing, and filters must survive past one render.

How it works

You call a setter. React schedules a new render with the new value.

Real world

Cart count, dark mode, open/closed menu, form drafts.

Analogy: props are a letter someone handed you. State is a notebook you write in. You do not scribble on the letter.

What is it?

useState is the hook that gives you memory

A hook is a function whose name starts with use. Call it at the top of a component — not inside loops or ifs.

Why

Function components would otherwise forget everything after each render.

How

Returns a pair: current value + a setter function.

Rule

Same order of hooks every render. Keep them at the top.

Simple example

A counter in eight lines

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

0 is the initial value — used only on the first render.

Live-type this in Vite. Click twice. Ask: “Did we touch the DOM?” Pause on the array destructuring: first item is the value, second is the updater.

State updates

Treat state as read-only. Replace it.

Do not mutate

tasks.push(newTask);
setTasks(tasks); // same array

Create a new value

setTasks([...tasks, newTask]);
setTasks(tasks.filter(t => t.id !== id));

React compares the new reference. If you mutate the old array, React may skip the update.

Safer updates

When the next value depends on the previous one

setCount(count + 1);
setCount(count + 1); // still +1 — both saw the same count

setCount(c => c + 1);
setCount(c => c + 1); // +2 — each uses the latest queued value

Use the function form for counters, toggles, and “add one more item.”

Demo two buttons: one with count+1 twice in the same handler, one with functional updates. Students remember this when they double-click Add.

What is it?

Events in React are named in camelCase

You pass a function. React calls it when the user acts. The first argument is the event object.

onClick

Buttons, cards, icons.

onChange

Inputs, selects, textareas.

onSubmit

Forms. Call preventDefault().

How events work

Pass the function. Do not call it in JSX.

Runs immediately (wrong)

<button onClick={handleDelete()}>

Runs on click (right)

<button onClick={handleDelete}>
<button onClick={() => handleDelete(id)}>

Need an argument? Wrap in an arrow function.

What is it?

A controlled input lets React own the value

The input’s value comes from state. onChange writes back. One source of truth.

Why

You can validate, disable Submit, and reset the field from code.

How

value={text} plus onChange={e => setText(e.target.value)}.

Real world

Search boxes, login forms, checkout fields.

Simple example

Name field that React can read

function NameForm() {
  const [name, setName] = useState("");
  function handleSubmit(e) {
    e.preventDefault();
    alert("Hello " + name);
    setName("");
  }
  return (
    <form onSubmit={handleSubmit}>
      <input value={name} onChange={e => setName(e.target.value)} />
      <button type="submit">Save</button>
    </form>
  );
}
Show what happens without preventDefault (page reload). Show an uncontrolled input with defaultValue vs controlled — students feel the difference when you try to clear the box.

Conditional UI

The screen is a function of state

Ternary

{isOn ? "On" : "Off"}

And

{error && <p>{error}</p>}

Early return

if (!open) return null;

Why is {count && <p>Items</p>} a trap when count is 0?

Because 0 is rendered on the page. Prefer count > 0 &&.

Rendering dynamic data

Lists come from arrays, not copy-pasted JSX

{tasks.map(task => (
  <li key={task.id}>
    {task.title}
  </li>
))}

Why keys?

React matches old items to new ones. Stable ids beat array index when you delete or reorder.

Shape

Each task: id, title, done. Generate ids with crypto.randomUUID() or a counter.

Component communication

State down. Events up.

Siblings do not talk sideways. They share a parent who holds the list.

Draw this on the board before coding Todo. Students who skip lifting state will put tasks inside the input component and wonder why the list cannot see them.

How lifting looks in code

// App.jsx owns tasks
<TodoForm onAdd={addTask} />
<TodoList tasks={tasks} onToggle={toggle} onDelete={remove} />

// TodoItem.jsx never calls useState for the list
<button onClick={() => onDelete(task.id)}>Delete</button>

If two children need the same data, move that data up one level.

Live coding target

function addTask(e) {
  e.preventDefault();
  const title = text.trim();
  if (!title) return;
  setTasks(prev => [...prev, { id: crypto.randomUUID(), title, done: false }]);
  setText("");
}

function toggle(id) {
  setTasks(prev => prev.map(t => t.id === id ? { ...t, done: !t.done } : t));
}

Recap

What we learned

State

Memory that triggers a re-render when it changes.

useState

Value + setter. Replace, do not mutate.

Events

Pass functions. Prevent default on forms.

Lists + lift

Map with keys. Parent owns shared data.

Common mistakes to avoid tonight

  • Calling the handler in JSX: onClick={fn()}.
  • Mutating arrays and objects, then wondering why the UI is stale.
  • Using array index as a key while deleting items.
  • Keeping two copies of the same list (raw + filtered).
  • Putting list state inside a child that the list cannot see.

Key takeaways

  1. UI is a snapshot of state.
  2. Props go down. Events go up.
  3. Controlled inputs make forms predictable.
  4. New arrays and objects, not mutations.
  5. Derive filtered views. Do not store them twice.
