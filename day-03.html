Problem → solution

Floats and absolute positioning do not scale

Problem

Yesterday’s cards stack. Forcing them with float or position breaks wrapping, centering, and equal heights.

Solution

Layout systems: Flexbox for one direction, Grid for two. Gap for spacing.

Technology: Flex + Grid. Result: navbars and card rows that can wrap.

Flexbox

A container that arranges children in one direction

What: a row or a column with alignment superpowers. Why: navbars, button groups, “logo left / links right”.

.nav {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 16px;
}

Flex direction

Row is the default. Column is a stacked flex.

Row

flex-direction: row;

Main axis = left to right. Navbar links.

Column

flex-direction: column;

Main axis = top to bottom. Mobile menu. Card body.

Alignment

Main axis vs cross axis — say it out loud

PropertyControlsCommon values
justify-contentMain axisflex-start, center, space-between, space-around
align-itemsCross axisstretch, center, flex-start, flex-end
align-selfOne childoverride stretch

If the nav is a row, which property pushes the logo left and the links right?

Answer: justify-content: space-between. align-items: center vertically centers the logo with the links.

Spacing

Prefer gap over margin on every child

Old habit

Each card has margin-right: 16px. The last card still has extra space. Wrapping looks uneven.

Better

.row {
  display: flex;
  gap: 16px;
}

Gap is spacing between items. Padding is still for air inside a card.

Flex wrap, grow, shrink

Rows must be allowed to break

.features {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}
.card { flex: 1 1 240px; } /* grow | shrink | basis */

Read 1 1 240px as: “try 240px, grow if there is room, shrink if not.”

CSS Grid

A container that arranges children in two dimensions

What: rows and columns at once. Why: feature sections, photo galleries, “equal height cards in a grid”.

.features {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;
  gap: 16px;
}

Grid tracks

fr is a share of leftover space

grid-template-columns: repeat(3, 1fr);
grid-template-columns: 200px 1fr;
grid-template-rows: auto 1fr auto;

How

Sidebar 200px, main takes the rest. Header / content / footer rows: auto, 1fr, auto.

Grid alignment

The grid has its own justify and align

PropertyUse
justify-items / align-itemsHow each cell’s content sits
justify-content / align-contentHow the whole grid sits if tracks don’t fill the container
place-items: centerShortcut for both axes — hero badges, empty states

Flex vs Grid

One direction vs two. Not a rivalry.

Flexbox

Content-driven row/column

Nav, toolbars, aligning an icon with a label.

Grid

Layout-driven areas

Page regions, card matrices, overlapping hero art later.

Would you build a 3-column “Our drinks” section with Flex or Grid first? Why?

Either works. Prefer Grid for equal columns. Flex wrap + basis is the fallback they already know.

Responsive problem

A 3-column grid on a 360px screen is cruelty

Solution: change the number of columns when the viewport crosses a breakpoint. Technology: media queries.

Media queries

CSS that only applies when a condition is true

.features {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}
@media (min-width: 768px) {
  .features { grid-template-columns: 1fr 1fr 1fr; }
}

Put the query after the base rule. Inside the query, only write what changes.

Mobile-first

Write the small layout as the default

Desktop-first

Start with 3 columns, then max-width queries to smash them. Easy to forget a phone.

Mobile-first

Start with 1 column. Enhance with min-width. The phone always works.

This course uses mobile-first. It matches how we will write Tailwind prefixes tomorrow.

Breakpoints we will use

Pick a few. Do not invent 12.

~640px

Large phones / small tablets. Optional.

~768px

Our main “now we can do 2–3 columns”.

~1024px

Comfortable desktop padding and max-width.

Also set max-width on the page (1100–1200px) and center it. Giant screens should not stretch text to 2000px.

The viewport meta

Without this tag, phones pretend they are 980px wide

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

You already used this on Day 1. If a “responsive” page looks zoomed-out on a phone, this line is missing.

Developer tools

Layout is debugged, not guessed

  1. Right-click → Inspect. Toggle device toolbar (phone icon).
  2. Watch the width number as you drag.
  3. Select a flex/grid container — Chrome draws the tracks.
  4. Look for overflow: a child with a fixed width is usually the villain.
  5. Uncheck properties live. If the bug vanishes, you found it.
Demo device mode on the live navbar. Show 375, 768, 1280. Show the overflow scrollbar as a “you failed this width” signal.

Recap

What we learned

Flexbox

One-axis layout, alignment, wrap, gap.

Grid

Two-axis tracks with fr and repeat.

Responsive

Mobile-first + min-width queries.

DevTools

Device mode finds overflow before users do.

Common mistakes

  • Using Grid for a simple navbar (Flex is clearer).
  • Forgetting flex-wrap so items squash or overflow.
  • Desktop-first queries and a broken phone layout.
  • Missing viewport meta — “responsive CSS” never engages.
  • Fixed pixel widths on images and cards.

Key takeaways

  1. Flex = one direction. Grid = rows and columns.
  2. Gap beats random child margins.
  3. Start from the small screen; enhance upward.
  4. A few breakpoints beat a unique rule for every device.
  5. Inspect, resize, fix overflow. That is professional layout work.
