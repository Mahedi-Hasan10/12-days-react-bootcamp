Scope

Where a name is visible

Scope is the rule: a variable lives inside the block that created it.

const appName = "Search"; // global to this file

function search(term) {
  const q = term.trim(); // only inside search
  if (q) {
    const url = `/users?q=${q}`; // only inside if
  }
  // console.log(url); // Error
}

Why

Stops accidental overwrites. Keeps data private.

How

let/const are block-scoped { }.

Real world

A loop index should not leak into the next function.

Callbacks

A function you pass to be called later

btn.addEventListener("click", handleClick);
// handleClick is a callback — we do not call it now

setTimeout(() => {
  console.log("2 seconds later");
}, 2000);

Why they exist: some work finishes later (timer, click, network). You hand over a “when you’re done, run this.”

The callback problem

Nested “later” becomes hard to read

getUser(id, (user) => {
  getPosts(user.id, (posts) => {
    getComments(posts[0].id, (comments) => {
      render(comments);
    });
  });
});

This is why promises and async/await were invented: same waiting, flatter code.

Promises

An object that represents a future value

A promise is pending, then fulfilled (success) or rejected (failure).

pending
→
fulfilled + data
pending
→
rejected + error
fetch(url)
  .then((res) => res.json())
  .then((data) => console.log(data))
  .catch((err) => console.error(err));

async / await

Write async code so it looks step-by-step

async function loadUsers() {
  const res = await fetch(url);
  const data = await res.json();
  return data;
}

async

Marks a function that can pause. It returns a promise.

await

Pause until that promise settles. Only inside async.

This is the style we use for the rest of the course — including React later.

try / catch

Networks fail. Your app should not go silent.

async function loadUsers() {
  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error("Request failed");
    return await res.json();
  } catch (err) {
    console.error(err);
    status.textContent = "Could not load users.";
  }
}

try = hopeful path. catch = recovery path. Always tell the human.

Same wait. Cleaner code over time.

JSON

The common language of APIs

JSON is text that looks like a JS object. Servers send it. You parse it into real objects.

// text on the wire
'{ "id": 1, "name": "Leanne Graham" }'

const user = JSON.parse(text);
const textAgain = JSON.stringify(user);

res.json() is fetch doing parse for you. Keys are quoted. No functions inside JSON.

Status codes you will actually see

200

OK — use the JSON.

404

Not found — wrong URL or id.

500

Server broke — retry later.

Failed fetch

No network / blocked — catch.

Your UI does not need to lecture HTTP. Map these to “loaded”, “not found”, or “try again.”

Fetch API

The browser’s built-in HTTP tool

What

fetch(url) returns a promise for a Response.

Why

No extra library for basic GET.

How

await fetch → check ok → await json → use data.

A 404 still “succeeds” as a Response. Always check res.ok before trusting JSON.

Loading state

Tell the truth while you wait

status.textContent = "Loading…";
try {
  const users = await loadUsers();
  status.textContent = "";
  render(users);
} catch {
  status.textContent = "Something went wrong.";
}

Three UI modes: loading, success, error. Never leave the last list looking “current” if a new search failed.

Error handling

Different failures, one user-facing message

No network

fetch throws. catch it.

Bad status

404 / 500. throw if !res.ok.

Empty result

Not an error. Show “No users found.”

Putting it on the page

Same render pattern as Todo

function render(users) {
  list.innerHTML = users
    .map((u) => `
      <li>
        <strong>${u.name}</strong>
        <p>${u.email}</p>
      </li>`)
    .join("");
}

Data source changed (API). UI skill did not (map → HTML).

Live coding · search flow

Filter after you fetch

const q = input.value.toLowerCase().trim();
const users = await loadUsers();
const matches = users.filter((u) =>
  u.name.toLowerCase().includes(q)
);
render(matches);

JSONPlaceholder has no search query. Client-side filter is the honest approach for this API.

Recap

What we learned

Waiting

Callbacks → promises → async/await.

Safety

try/catch, res.ok, user-facing errors.

JSON + REST

GET a resource, parse, render.

UX

Loading and empty are real states.

Common mistakes

  • Forgetting await — you log a Promise, not data.
  • Assuming fetch throws on 404.
  • No loading state — UI looks frozen.
  • Mixing search filter with a second fetch you did not need.
  • Putting API keys in frontend code (we avoid keyed APIs in class).

Key takeaways

  1. Scope keeps names from leaking.
  2. Async work returns later — await it.
  3. JSON is data as text; parse before you render.
  4. GET + fetch is how the browser talks to APIs.
  5. Every request needs loading and error UI.
