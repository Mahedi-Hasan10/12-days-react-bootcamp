Problems with traditional DOM

  • innerHTML rebuilds too much or not enough.

Props

Inputs to a component — like function parameters

function ProfileCard({ name, role }) {
  return (
    <article className="rounded-2xl bg-white p-6 shadow">
      <h3>{name}</h3>
      <p>{role}</p>
    </article>
  );
}

<ProfileCard name="Ada" role="Engineer" />

Parent decides the data. Child decides the look. Tailwind classes are welcome now.

Destructure props in the parameter list. Show both props.name and { name }.

Why props

What

Read-only data from parent to child.

Why

One ProfileCard, many people.

How

Attributes in JSX become the props object.

Do not mutate props. Tomorrow you will learn state for values that change.

Composition

Build screens by nesting components

function App() {
  return (
    <main className="mx-auto max-w-5xl p-8">
      <Header title="Our team" />
      <ProfileCard name="Ada" role="Engineer" />
      <ProfileCard name="Grace" role="Lead" />
    </main>
  );
}

Small components. App is the table of contents.

Rendering lists

map in JSX — with a key

const members = [
  { id: 1, name: "Ada", role: "Engineer" },
  { id: 2, name: "Grace", role: "Lead" }
];

{members.map((m) => (
  <ProfileCard key={m.id} name={m.name} role={m.role} />
))}

key must be stable and unique. Do not use array index if the list can reorder.

Conditional rendering

Show UI only when it makes sense

function Badge({ featured }) {
  return (
    <div>
      {featured ? (
        <span className="text-teal-800">Featured</span>
      ) : null}
      {featured && <span>★</span>}
    </div>
  );
}

Ternary when you have two branches. && when you show or nothing. Avoid 0 && ... surprises with counts — use a boolean.

How React gets on the page

One HTML node. React owns the tree inside it.

// index.html
<div id="root"></div>

// src/main.jsx
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(<App />);

You still have HTML — but only as a mount point. The UI lives in components.

Creating a React project

Vite is the fast modern starter

npm create vite@latest team-profiles -- --template react
cd team-profiles
npm install
npm run dev

Vite serves your app locally with hot reload. You edit a component; the browser updates.

Install Node before class if possible. Walk the first student through the terminal. Open the localhost URL together.

Project structure

Know the folders before you invent new ones

Recap

What we learned

Why React

Describe UI from data; stop fragile DOM patches.

Components

Functions that return JSX.

Props

Parent-to-child configuration.

Lists

map, keys, conditionals, composition, Vite structure.

Common mistakes

  • Lowercase component names — React treats them as HTML tags.
  • Missing key on lists (or using index carelessly).
  • class instead of className.
  • Returning two sibling elements without a wrapper.
  • Trying to use document.querySelector inside React as the main strategy.

Key takeaways

  1. React exists because manual DOM does not scale.
  2. A component is a function returning JSX.
  3. Props are inputs. Do not mutate them.
  4. Lists need map and stable keys.
  5. Vite is how we start a real React project.
