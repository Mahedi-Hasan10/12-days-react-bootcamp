Interactive question

When you click “Add to cart”, what actually changes on the page?

Guess

“The HTML file on disk is rewritten.”

Guess

“A new website is downloaded.”

Reality

JavaScript updates the live document in memory — the DOM.

What is it?

The DOM is the live tree of your page

DOM means Document Object Model. The browser turns HTML into objects you can read and change with JavaScript.

Why

Without a model of the page, JS cannot find the button you clicked.

How

HTML → parse → tree of nodes → your script walks the tree.

Real world

Changing a like count without refreshing Instagram.

HTML is nested. The DOM is nested.

You never edit the .html file at click time. You edit the tree the browser already built.

Selecting elements

Find the node before you change it

const title = document.querySelector("#title");
const items = document.querySelectorAll(".task");
const input = document.getElementById("task-input");
ToolReturnsUse when
querySelectorFirst matchOne button, one title
querySelectorAllList of matchesEvery task row
getElementByIdOne idFast, unique ids
Ids must be unique. Prefer querySelector with #id and .class — same mental model as CSS.

Changing content

The page is not frozen

title.textContent = "My Todos";
title.innerHTML = "My <em>Todos</em>";
input.value = ""; // clear the field

textContent

Safe for user text. No HTML parsing.

innerHTML

Parses tags. Do not dump untrusted user input here.

Changing styles

Classes beat inline spaghetti

item.classList.add("done");
item.classList.remove("done");
item.classList.toggle("done");
// last resort:
item.style.color = "green";

Put look in CSS. Use JS to turn classes on and off. That is how a completed todo gets a strike-through.

Events

The browser tells you when something happens

An event is a signal: click, input, submit, keydown. Your job is to listen and respond.

Event listeners

addEventListener is the standard tool

const btn = document.querySelector("#go");

btn.addEventListener("click", function () {
  console.log("clicked");
});

Do not put JS in HTML onclick="..." for this course. Keep behavior in the script file.

Click events

The simplest interactive app

let count = 0;
const label = document.querySelector("#count");

document.querySelector("#plus")
  .addEventListener("click", () => {
    count += 1;
    label.textContent = count;
  });

Pattern you will reuse forever: update data, then update the UI.

Build this counter live. It is the mental model for Todo and later useState.

Input handling

Read what the user typed

const input = document.querySelector("#task-input");
const preview = document.querySelector("#preview");

input.addEventListener("input", () => {
  preview.textContent = input.value;
});

input event

Fires on every keystroke. Great for live preview.

change event

Fires when the field loses focus (or select changes).

Forms

Stop the refresh. Handle submit yourself.

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const text = input.value.trim();
  if (!text) return;
  addTask(text);
  input.value = "";
});

preventDefault is not optional. Without it, the browser posts the form and your list vanishes.

Arrow functions

A compact function expression

const double = (n) => n * 2;
const greet = (name) => {
  return `Hi, ${name}`;
};

btn.addEventListener("click", () => {
  console.log("clicked");
});

Same idea as function. You will see arrows everywhere in React.

Template literals

Backticks, not plus signs

const name = "Nila";
const left = 3;
const msg = `${name} has ${left} tasks left`;

Use ${expression} inside backticks. Great for list item HTML you build in JS.

Destructuring

Unpack values by name or position

const task = { id: 1, text: "Study JS", done: false };
const { text, done } = task;

const marks = [80, 90, 70];
const [math, english] = marks;

Why: stop writing task.text ten times when you only need two fields.

Spread operator

Copy, then change — do not mutate blindly

const tasks = ["Read", "Code"];
const next = [...tasks, "Rest"];

const user = { name: "Ada", role: "dev" };
const updated = { ...user, role: "lead" };

React later prefers new arrays/objects instead of silent mutation. Learn the habit now.

forEach

Do something for every item

tasks.forEach((task) => {
  console.log(task.text);
});

Use forEach for side effects: logging, appending DOM nodes. Use map when you want a new array back.

map

Turn every item into something else

const names = ["ada", "nila"];
const labels = names.map((n) => n.toUpperCase());
// ["ADA", "NILA"]

Why

UI lists are data mapped into HTML or components.

Real world

Products → cards. Todos → list items.

filter and find

Keep some items. Find one item.

const open = tasks.filter((t) => !t.done);
const one = tasks.find((t) => t.id === 3);
filterfind
ReturnsNew array (0–many)First match or undefined
UseActive todos, search resultsThe todo you just clicked

Recap

What we learned

DOM

The live tree. Select, then change.

Events

Listen, preventDefault on forms, update UI.

Modern JS

Arrows, templates, destructuring, spread.

Arrays

forEach, map, filter, find — data → UI.

Common mistakes

  • Script in <head> without defer — elements are null.
  • Forgetting preventDefault on submit.
  • Updating the array but never calling render().
  • Using innerHTML with raw user text unsafely.
  • Mutating arrays in confusing ways instead of filter/map.

Key takeaways

  1. The DOM is the page as objects.
  2. Select → listen → update data → render.
  3. Forms need preventDefault.
  4. map/filter/find replace many manual loops.
  5. This pattern is what React will later automate.
