Interactive question

What happens if you call fetch directly in the body of a function component?

Guess A

It runs once, like useState’s initial value.

Guess B

It runs every render — possibly an infinite loop.

Guess C

React blocks it automatically.

Answer B. Render must be pure. Fetch is a side effect. If setState happens after fetch, you re-render and fetch again. That is why useEffect exists.

What is it?

useEffect runs after React paints the screen

Use it for work that talks to the outside world: APIs, localStorage, timers, document title.

Why we need it

Rendering should be a calculation. Effects are the “and also do this.”

How it works

You pass a function and a dependency array. React decides when to re-run it.

Real world

Load products when the shop page opens.

The three dependency patterns

When does the effect run?

ArrayRunsUse for
[]Once after mountInitial fetch
[query]When query changesSearch as you type (or on submit)

Draw the timeline: render → paint → effect. Stress empty array vs missing array. Students mix these up all week.

Simple example

Set the tab title from state

import { useState, useEffect } from "react";

function TitleDemo() {
  const [name, setName] = useState("Guest");
  useEffect(() => {
    document.title = "Hello, " + name;
  }, [name]);
  return <input value={name} onChange={e => setName(e.target.value)} />;
}

No network yet. Same hook. Same rules.

Cleanup

Return a function to undo the effect

useEffect(() => {
  const id = setInterval(() => console.log("tick"), 1000);
  return () => clearInterval(id);
}, []);

For fetch, cleanup often means an AbortController or an ignore flag so a slow response does not overwrite newer data.

Loading and error

Three rooms. Only one is open.

Loading

true until the first response. Spinner or “Loading…”

Error

Network fail or !res.ok. Message + Retry.

Success

Array in state. Map to cards. Empty array is still success.

Is an empty product list an error?

Usually no. Show an empty state, not a red banner.

How fetching looks

useEffect(() => {
  let ignore = false;
  async function load() {
    setLoading(true);
    setError("");
    try {
      const res = await fetch("https://fakestoreapi.com/products");
      if (!res.ok) throw new Error("Request failed");
      const data = await res.json();
      if (!ignore) setProducts(data);
    } catch (err) {
      if (!ignore) setError(err.message);
    } finally {
      if (!ignore) setLoading(false);
    }
  }
  load();
  return () => { ignore = true; };
}, []);
Do not put async directly on the effect callback — React expects a cleanup function or nothing. Inner async function is the classroom pattern.

Search

Two valid designs. Pick one on purpose.

Filter locally

Fetch once. items.filter by title. Fast. Needs the full list.

Search on the server

Effect depends on query. New request each search. Needed when the list is huge.

Today: fetch all Fake Store products, then filter in memory. Tomorrow’s shop can reuse the same idea.

Controlled search box

const [query, setQuery] = useState("");
const visible = products.filter(p =>
  p.title.toLowerCase().includes(query.toLowerCase())
);

Derived data again: do not store visible in state unless you have a strong reason.

Search on submit

When the API is large, do not fetch on every keystroke

function handleSearch(e) {
  e.preventDefault();
  setSubmittedQuery(query);
}

useEffect(() => {
  // fetch using submittedQuery
}, [submittedQuery]);

Draft text in query. Network in an effect that depends on the submitted value.

Render the three rooms

Order matters: loading, then error, then data

{loading && <StatusMessage kind="loading" />}
{!loading && error && <StatusMessage kind="error" onRetry={retry} />}
{!loading && !error && (
  <ProductGrid items={visible} />
)}

Do not map undefined. Start products as [].

Public APIs in the browser

CORS is a browser rule, not a React bug

If the Network tab shows a CORS error, your fetch code may be fine. The server refused the browser origin.

Classroom fix

Switch to an API that allows public GET from browsers (Fake Store, JSONPlaceholder).

Not today

Do not disable the browser’s security. Do not paste random CORS-proxy URLs you do not understand.

If a student’s chosen homework API fails CORS, help them pick another. This is a common Day 10 panic.

Student practice #2 · 8 minutes

Retry button

Add retryCount state. Put it in the effect deps.

  1. Error banner includes “Try again”
  2. Clicking increments retryCount
  3. Effect re-runs and fetches again
This teaches deps without introducing a library. Alternative: extract load() and call it from both effect and button — also fine; mention both.

Student practice #3 · 8 minutes

Category chips from the API

  • Fake Store: /products/categories or unique category fields
  • Chip sets category state: "all" or a name
  • Filter by both query and category

Student practice #4 · 5 minutes

Empty search results

If visible.length === 0 and you are not loading, show “No matches for …” with the current query. Do not show a spinner.

Recap

What we learned

useEffect

After paint. Deps decide how often.

Fetch

Async inside the effect, not in render.

Status UI

Loading, error, empty, success.

Architecture

Fetch high. Cards stay dumb. Search derives.

Common mistakes to avoid tonight

  • Fetching in the component body.
  • Missing dependency array (loop) or wrong deps (stale query).
  • Ignoring res.ok and treating HTML error pages as JSON.
  • Putting fetch inside every card.
  • Leaving the user on a blank screen while the network thinks.

Key takeaways

  1. Render is pure. Effects do the messy work.
  2. Always design loading and error, not only the happy grid.
  3. Read the JSON shape before you write JSX.
  4. Reusable cards make Day 11 faster.
  5. Derived search beats a second stored list.
